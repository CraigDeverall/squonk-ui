# Footer

<ResizableCanvas of={FooterStories.Default} />

`Footer` renders the bottom landmark of a page — semantic `<footer>`, surface background, top border, smaller text scale. Like `Header`, it's a content-agnostic shell; the consumer composes what goes inside (copyright, links, address, social). Layout knobs are deliberately absent: use a `Split` / `Cluster` / `Grid` inside to control "copyright left, links right" or "three-column nav".

<Controls />

## Default

The standard copyright + nav split.

<InlineCodeExample>
  <Footer>
    <Split>
      <Text tone="muted">© 2026 Squonk</Text>
      <Cluster gap="md">
        <Link href="#" variant="muted">Privacy</Link>
        <Link href="#" variant="muted">Terms</Link>
        <Link href="#" variant="muted">Status</Link>
      </Cluster>
    </Split>
  </Footer>
</InlineCodeExample>

## Page tone

`tone="page"` removes the surface tint and sits flush with the page background — for layouts whose page bg is already a brand color and the surface stripe would look like a bug.

<InlineCodeExample>
  <Footer tone="page">
    <Text tone="muted">© 2026 Squonk</Text>
  </Footer>
</InlineCodeExample>

## Accessibility

- Renders a native `<footer>` landmark — at the top level of the page, screen readers announce it as `contentinfo`.
- A `<footer>` nested inside an `<article>` or `<section>` is a *section* footer, not the page contentinfo — still valid HTML, just not a landmark.
- Text contrast uses `theme.colors.text.secondary` against the surface background — verified to meet WCAG AA on both themes.

## Common pitfalls

- **Don't pin the Footer to the bottom of the viewport.** A footer that always shows is a *toolbar*, not a footer. Let it sit at the natural end of the page.
- **Don't ship multiple page-level Footers.** One per page; multiple `<footer>` elements without a containing landmark confuse screen-reader navigation.
- **Don't hardcode width inside.** Wrap link groups in a `Container` so wide monitors don't stretch the footer's link list into a thin ribbon.
- **Don't use `tone="page"` on the default theme.** It only helps when your page background is itself a strong color. On the standard white/dark page the surface tint *is* the visual separator.
