# Space and layout

Space comes from one scale built on an 8px step (the `spacingPx` primitive).
Components don't pick steps directly; they use space purposes, so every field,
dialog and list spaces itself the same way.

## Registers

`Presentation` sets the size of a region's controls for its job: `compact` for
dense admin screens, `default` for most of an app, `large` and `hero` for landing
and marketing pages. Control heights, padding and text all step together, so a row
of mixed controls always lines up. When to use each is on
[Density and registers](?path=/docs/patterns-density-and-registers--docs).

## Breakpoints

Layouts are mobile first: they start as one column and add columns as space allows.

| Name | From | Typical change |
| --- | --- | --- |
| `mobile` | 480px | Larger phones: side-by-side buttons |
| `tablet` | 768px | Sidebars appear; two-column forms |
| `desktop` | 1024px | Full app layouts |
| `wide` | 1280px | Extra columns, wider tables |

Test real narrow containers, not only the window width: a card in a sidebar is
narrow on any screen.

## Arranging components

The parent owns placement and spacing; children size themselves. Reach for a
layout primitive before writing layout CSS.

<SampleGrid narrow>
  <Specimen label="VStack: vertical flow">
    <VStack gap="sm">
      <Card variant="filled"><Text>Annual dues</Text></Card>
      <Card variant="filled"><Text>Swamp Fund levy</Text></Card>
    </VStack>
  </Specimen>
  <Specimen label="HStack: a row that can wrap">
    <HStack gap="sm" wrap>
      <Badge>Night watches</Badge>
      <Badge>Tear pools</Badge>

    </HStack>
  </Specimen>
  <Specimen label="Split: content and actions apart">
    <Split align="center">

    </Split>
  </Specimen>
  <Specimen label="Grid: a responsive collection">
    <Grid minColumnWidth="5rem" gap="sm">
      <Card variant="filled"><Text>Q1</Text></Card>
      <Card variant="filled"><Text>Q2</Text></Card>
      <Card variant="filled"><Text>Q3</Text></Card>
    </Grid>
  </Specimen>
</SampleGrid>

| Need | Use |
| --- | --- |
| Stack things vertically | [VStack](?path=/docs/layout-primitives-vstack--docs) |
| A row, wrapping if needed | [HStack](?path=/docs/layout-primitives-hstack--docs) or [Cluster](?path=/docs/layout-cluster--docs) |
| Content on one side, actions on the other | [Split](?path=/docs/layout-split--docs) |
| A collection of cards | [Grid](?path=/docs/layout-primitives-grid--docs) |
| Limit reading width | [Container](?path=/docs/layout-primitives-container--docs) |
| A padded, painted region | [Block](?path=/docs/layout-primitives-block--docs) |
| A bounded scrolling area | [ScrollBox](?path=/docs/layout-primitives-scrollbox--docs) |
| Keep media in proportion | [AspectRatio](?path=/docs/layout-primitives-aspectratio--docs) |
| A full screen with header and sidebar | [Page](?path=/docs/layout-page--docs) |

Avoid nested scroll areas unless the task needs them; a wide table may scroll
sideways while the page stays put. Use `gap` on the parent rather than margins on
repeated children.

For whole screens (app shells, reading pages, landing pages, resizable
workspaces) and how they change across breakpoints, see
[Page layouts and app shells](?path=/docs/patterns-page-layouts-and-app-shells--docs).
