# App navigation

The frame around a signed-in app: where you are, where you can go, and how to
get back. Compose it from [Header](?path=/docs/layout-header--docs),
[Sidebar](?path=/docs/layout-sidebar--docs), [NavList](?path=/docs/components-navigation-navlist--docs)
for the links between pages, [Breadcrumb](?path=/docs/functional-breadcrumb--docs),
[Link](?path=/docs/functional-link--docs) and, on phones, a
[Drawer](?path=/docs/functional-drawer--docs) for the menu.

</Example>

## The rules

- **Name each navigation landmark** (`<nav aria-label="Account">`) so screen-reader
  users can tell two apart.
- **Mark the current page** with `aria-current="page"` and a visible style, and
  make the page's heading match the item.
- **Keep the reading order sensible** when the sidebar stacks above the content
  on a phone, and add a skip link when the navigation is long.
- **Your app owns routing.** Pass your router's link component to Breadcrumb's
  `linkAs`; Sidebar is a layout region, not a router or a modal.

## Tabs switch views; links change pages

Use [Tabs](?path=/docs/functional-tabs--docs) to switch between views of one
thing on the same page. Use links for places in the app.
