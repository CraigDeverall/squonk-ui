# Server errors

<ResizableCanvas of={Examples.ServerErrors} defaultHeight={440} />

Return the API's answer from `validators.onSubmitAsync`:

- `{ fields: { username: "That username is taken. Try another one." } }` puts a
  message on a field, as if the client had found it.
- `{ form: "We couldn't create your login just now…" }` is for problems that
  belong to no field. It shows in the error summary.
- Return `undefined` when everything is fine, and `onSubmit` runs.

The submit button is busy while the check runs, and a failed submit moves focus
to the summary as usual. Map your API's error codes to messages people can act
on; don't show the raw error.
